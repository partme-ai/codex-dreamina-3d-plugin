Two CI-only defects were found and fixed while establishing this gate; neither
was visible to the offline suite:

1. The distribution validator walked the whole tree, so it flagged a *companion*
   repository's own fixture (`companions/codex-dreamina-design-plugin/tests/test_distribution_v7.py`)
   as secret-like content. The scan now covers shipped content only. Fixed in
   `71fefe0`; `__pycache__` is excluded too, since generated bytecode embeds
   source literals.
2. A drift-guard test looked for the companion at the sibling path and skipped
   in CI, where the companion lives under `companions/` and is addressed by
   `CODEX_BLENDER_REPO`. The strict gate treats any skip as failure. Fixed in
   `adec086`.

Both were reproduced and verified locally against a faithful rehearsal of the
CI layout (checkout directory named `codex-dreamina-3d-plugin`, `companions/`
populated from the real sibling repositories, `CODEX_*_REPO` set, real `.git`
present) before pushing.

## Accepted limitations

- **Maya** remains an experimental fixture path with runtime status `NOT_RUN`.
  Frontmatter is `status: experimental`, the manifest carries no Maya claim, and
  the router flags it before routing. Outside the release scope.
- **Windows** is outside the release scope.
- **`jimeng_web`** is `OPTIONAL_UNAVAILABLE` while the user-installed official
  uploader is absent. Reported honestly; a Jimeng Web link terminates at
  `JimengLinkReady`, never at Seedance `Completed`.
- **CI runs on `ubuntu-latest`.** Accepted: CI exercises only deterministic,
  platform-independent gates; the Blender/macOS runtime acceptance is the
  separate step above, and CI makes no runtime claim.
- **The interactive fresh-task UI step** is verified only through its
  deterministic precondition (see Task 5).
